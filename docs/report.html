Technical Report — VKU Field Survey PWA

Campus facility teams inspect classrooms, labs, and utilities where Wi-Fi is weak or absent. This Progressive Web App installs to the home screen, captures inspections with zero network, stores records in IndexedDB, and queues submissions until HTTPS connectivity returns.

1. Five PWA criteria

CriterionImplementation
InstallableWeb App Manifest, standalone display, maskable icons, install prompt.
Offline-firstService Worker Cache API (app shell) + IndexedDB (surveys).
Fast & responsiveCache-First boot, 720px column, mobile tap targets.
EngagingQueued-offline notifications; Badging API on launcher icon.
SecureSW registers only in production over HTTPS / localhost.

3. Service Worker lifecycle

Register in main.ts
↓
Install  → pre-cache App Shell (HTML, CSS, JS, icons)
↓
Activate → delete deprecated cache versions
↓
Fetch    → intercept HTTP requests and apply caching strategies

4. Five caching strategies

  1. Cache-First — app shell (HTML, JS, CSS, icons, navigations).
  2. Network-First — /api/* live data; cache fallback when offline.
  3. Stale-While-Revalidate — manifest and version.json.
  4. Cache-Only — /offline.html.
  5. Network-Only — /auth/* (do not cache tokens).

5. IndexedDB

Database vku-field-survey, object store surveys, keyPath id, indexes on status and createdAt. Each record holds facility metadata, optional compressed JPEG, GPS, and status queued or synced. Offline submits increment the app badge and can fire a local notification.

6. Verification

npm run build && npm run preview. DevTools → Offline → submit inspection → confirm IndexedDB row → restore network → status becomes synced. Deploy with npm run deploy to Cloudflare Workers (HTTPS).
